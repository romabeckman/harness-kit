# Session Steering
Guides the runtime classification and application of developer steering overrides in the orchestration loop.

## OVERVIEW
Session steering permits developers to inject custom instructions and execute state rollbacks dynamically. It relies on the SteeringAnalyzer classification to steer the orchestrator state machine.

## FOLDER STRUCTURE
<folder_structure>
sdk/src/
├── orchestrator/
│   ├── SteeringAnalyzer.ts       # Parses developer text into steering actions
│   ├── HarnessOrchestrator.ts    # Executes state machine rollbacks and applies overrides
│   └── services/
│       └── SteeringService.ts    # Applies steering actions to config and state
└── file-state/
    └── types.ts                  # Defines steering rules configuration schema
</folder_structure>

## STEERING ACTIONS
- **add_rule**: Injects a custom instruction to direct agent code generation or testing.
- **rollback**: Reverts the state machine to a previous phase, resetting task statuses when target is Phase A or Phase B.
- **override_score**: Manually overrides TL (Tech Lead) and Adv (Adversarial) validation scores.

## HOW TO APPLY STEERING ACTIONS
### Prerequisites
1. SteeringAction array generated by the CLI or user interface.
2. Bootstrap config file initialized.

### Steps
1. Parse the developer command-line text input through `SteeringAnalyzer`.
2. Invoke `applySteeringActions` on `HarnessOrchestrator`.
3. Save updated rules and phase state to `BOOTSTRAP-CONFIG.json`.

<code_example>
# CORRECT: Apply steering actions and reset task status on rollback
if (action.type === 'rollback') {
  const target = action.targetPhase as Phase
  this.state.currentPhase = target
  config.currentPhase = target
  if (target === Phase.DEVELOPMENT || target === Phase.PLANNING) {
    this.fsm.updateTaskStatus(active.id, t.taskId, '-', 'NOT_STARTED')
  }
}

# WRONG: Rollback phase state without resetting task execution statuses
if (action.type === 'rollback') {
  this.state.currentPhase = action.targetPhase // Leaves tasks in COMPLETED state
}
</code_example>

## PARAMETERS / CONFIGURATIONS
| Name | Type | Required | Description | Default |
|------|------|----------|-------------|---------|
| steeringRules.user | string[] | No | Custom runtime rules injected by the user | [] |
| steeringRules.bootstrap | string[] | No | Rules applied during bootstrap initialization | [...] |
| steeringRules.PLANNING | string[] | No | Rules applied during Phase A scope refinement | [...] |
| steeringRules.implementation | string[] | No | Rules applied during Phase B implementation | [...] |

## BEST PRACTICES
REQUIRED: Use rollbacks to reset implementation states when refactoring existing tasks.
REQUIRED: Flatten all phase-specific rules along with user overrides before invoking any agent.
FORBIDDEN: Modifying steering configurations without persisting the updated bootstrap config to disk.
