## ARCHITECTURE SUMMARY
Pattern: Ports/adapters with chain-of-responsibility orchestrator.
Stack: TypeScript, Node.js, Vitest, Docker.
Flow: BOOTSTRAP -> optional REFINEMENT -> PLANNING -> DEVELOPMENT -> REVIEW -> TRANSITION -> MEMORY -> DEPLOY -> HALTED; CASCADE_BLOCKED handles dependency failures. QA plans validate, probe, execute, analyze, and report. It persists artifacts, retries transient probes, and restarts marked managed browser targets. Profiles cover HTTP, browser, mobile, accessibility, MCP, CLI, WebSocket, and security.
Modes: explicit `thinking`/`deep_thinking` enable REFINEMENT; undefined fallback disables it; `quick` skips Review but keeps Memory; `fast` needs `--refine`.
Layers: domain/orchestration, application, adapters, composition. QA CLI: `run`, `report`, `exploratory`, `auth`; analysis needs `--analysis` or analyzed resume. Reports support JSON, HTML, Markdown, and developer artifacts. Auth profiles redact evidence; authenticated browser runs omit login actions; `authProfile: "none"` scopes anonymous scenarios; authenticated WebSocket scenarios block.
QA uses routed docs, memory, and JSON handoffs; repair prompts escape NUL; renewal scopes actionable items; reset runs scope actionable results; verified targets expire after 30 days.
QA reuses runner sessions; browsers use isolated contexts and selector/URL waits; CLI executions start fresh.
DI: Inject ports through constructors or orchestrator options; use registries and factories at composition boundaries.
REQUIRED: Propagate AbortSignal/prompt transport, resolve phase model/effort, use atomic replacement, validate DTOs, and run RTK checks.
PROHIBITED: Bind orchestration decisions to concrete runners, place HTTP transport in use cases, or bypass state adapters.
