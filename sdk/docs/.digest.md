## ARCHITECTURE SUMMARY
Pattern: Ports and Adapters around a Chain-of-Responsibility orchestrator.
Stack: TypeScript 7.0.2, Node.js, Vitest 5.0.0, Docker.
Flow: BOOTSTRAP -> optional REFINEMENT -> PLANNING -> DEVELOPMENT -> REVIEW -> TRANSITION -> MEMORY -> DEPLOY -> HALTED; CASCADE_BLOCKED handles dependency failures. Independent QA runs planning, validation, target probe, execution, adaptive analysis, and optional reporting. It persists immutable numbered plans, scoped run state, reports, and evidence. Profiles cover HTTP, browser, mobile, accessibility, MCP, CLI, WebSocket, and security. SDK tests use synthetic data and injected drivers.
Layers: domain/orchestration, application, inbound adapters, outbound adapters, registration/composition. QA CLI exposes `hrns qa run`, `hrns qa report`, and `hrns qa exploratory`. Exploratory executes the latest version of every saved plan sequentially and persists one deterministic global JSON report. Interactive QA renewal sends only FAILED/BLOCKED scenarios and confirms mode, deploy, and supplied model/effort overrides. QA prompts use strict JSON contracts. Reports include open points and an enforced 8,000-character Markdown cap.
QA planning reads routed docs and advisory hints from `docs/qa/execution-memory.json`. Verified targets expire after 30 days; explicit wins. Adaptive revisions preserve executed scenarios; progress includes reasons and warnings.
One QA execution reuses its first runner session across all agent calls. Separate CLI executions start fresh sessions.
DI: Inject ports through constructors or orchestrator options; use registries and factories at composition boundaries.
REQUIRED: Propagate AbortSignal, expose prompt transport through `IAgentRunner`, resolve model/effort per phase including QA, use atomic file replacement, validate transport DTOs, and run checks through RTK.
PROHIBITED: Bind orchestration decisions to concrete runners, place HTTP transport in use cases, or bypass state adapters.
