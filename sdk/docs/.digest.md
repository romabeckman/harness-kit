## ARCHITECTURE SUMMARY
Pattern: Ports and Adapters with a Chain-of-Responsibility orchestrator.
Stack: TypeScript 7.0.2, Node.js, Vitest 5.0.0, Docker.
Flow: BOOTSTRAP -> optional REFINEMENT -> PLANNING -> DEVELOPMENT -> REVIEW -> TRANSITION -> MEMORY -> DEPLOY -> HALTED; CASCADE_BLOCKED handles dependency failures. Independent QA plans, validates, probes, executes, analyzes, and reports. It persists artifacts, retries transient probes, and restarts marked managed browser targets. Profiles cover HTTP, browser, mobile, accessibility, MCP, CLI, WebSocket, and security.
Layers: domain/orchestration, application, adapters, composition. QA CLI exposes `run`, `report`, `exploratory`, and `auth`; analysis requires `--analysis` or `resume with analysis`. Report output writes JSON, HTML, Markdown, or LLM developer-scope artifacts; selected files overwrite atomically. HTML uses one evidence link per scenario; modal previews files with direct links. `.harness-kit/auth.json` supports environment or confirmed insecure literals. Curl/MCP/CLI evidence redacts secrets. Authenticated WebSocket scenarios block. Exploratory runs latest plans. Markdown caps at 8,000 characters.
QA phases use routed docs, memory, and JSON handoffs. Repair prompts encode raw NUL as `\\u0000`. Renewal preselects actionable scenarios and scopes checked items. `hrns run --reset --run <id>` scopes all actionable results. Verified targets expire after 30 days; explicit wins.
One QA execution reuses its first runner session across all agent calls. Separate CLI executions start fresh sessions.
DI: Inject ports through constructors or orchestrator options; use registries and factories at composition boundaries.
REQUIRED: Propagate AbortSignal, expose prompt transport through `IAgentRunner`, resolve model/effort per phase including QA, use atomic file replacement, validate transport DTOs, and run checks through RTK.
PROHIBITED: Bind orchestration decisions to concrete runners, place HTTP transport in use cases, or bypass state adapters.
