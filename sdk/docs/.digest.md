## ARCHITECTURE SUMMARY
Pattern: Ports and Adapters around a Chain-of-Responsibility orchestrator.
Stack: TypeScript 7.0.2, Node.js, Vitest 5.0.0, Docker.
Flow: BOOTSTRAP -> optional REFINEMENT -> PLANNING -> DEVELOPMENT -> REVIEW -> TRANSITION -> MEMORY -> DEPLOY -> HALTED; CASCADE_BLOCKED handles dependency failures. Independent QA runs planning, validation, probing, execution, analysis, and optional reporting. It persists plans, runs, evidence, and reports. Profiles cover HTTP, browser, mobile, accessibility, MCP, CLI, WebSocket, and security.
Layers: domain/orchestration, application, inbound adapters, outbound adapters, registration/composition. QA CLI exposes `hrns qa run`, `hrns qa report`, `hrns qa exploratory`, and `hrns qa auth`. `.harness-kit/auth.json` supports environment or confirmed insecure literals selected with `--auth`. Curl uses transient stdin config; Curl/MCP/CLI evidence redacts resolved values. CLI auth requires explicit mappings; authenticated WebSocket scenarios block. Resolved secrets stay out of plans, prompts, reports, and evidence. Exploratory runs latest saved plans and writes one global JSON report. QA prompts use strict JSON contracts; reports cap Markdown at 8,000 characters.
QA planning reads routed docs and advisory hints from `docs/qa/execution-memory.json`. Verified targets expire after 30 days; explicit wins. Adaptive revisions preserve executed scenarios; progress includes reasons and warnings.
One QA execution reuses its first runner session across all agent calls. Separate CLI executions start fresh sessions.
DI: Inject ports through constructors or orchestrator options; use registries and factories at composition boundaries.
REQUIRED: Propagate AbortSignal, expose prompt transport through `IAgentRunner`, resolve model/effort per phase including QA, use atomic file replacement, validate transport DTOs, and run checks through RTK.
PROHIBITED: Bind orchestration decisions to concrete runners, place HTTP transport in use cases, or bypass state adapters.
