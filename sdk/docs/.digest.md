## ARCHITECTURE SUMMARY
Pattern: Ports/adapters with chain-of-responsibility orchestrator.
Stack: TypeScript 7.0.2, Node.js, Vitest 5.0.0, Docker.
Flow: BOOTSTRAP -> optional REFINEMENT -> PLANNING -> DEVELOPMENT -> REVIEW -> TRANSITION -> MEMORY -> DEPLOY -> HALTED; CASCADE_BLOCKED handles dependency failures. QA plans validate, probe, execute, analyze, and report. It persists artifacts, retries transient probes, and restarts marked managed browser targets. Profiles cover HTTP, browser, mobile, accessibility, MCP, CLI, WebSocket, and security.
Layers: domain/orchestration, application, adapters, composition. QA CLI exposes `run`, `report`, `exploratory`, and `auth`; analysis requires `--analysis` or resume with analysis. Reports write JSON, HTML, Markdown, or developer artifacts. `.harness-kit/auth.json` supports env or confirmed literals. Planning and adaptive analysis receive only auth profile name/mode; non-`none` browser runs start authenticated and omit login actions; `authProfile: "none"` scopes anonymous/login scenarios. Curl/MCP/CLI evidence redacts secrets; safe body fields remain; logout redirects flag auth rejection. Authenticated WebSocket scenarios block.
QA phases use routed docs, memory, and JSON handoffs. Repair prompts encode raw NUL as `\\u0000`. Renewal preselects actionable scenarios and scopes checked items. `hrns run --reset --run <id>` scopes all actionable results. Verified targets expire after 30 days; explicit wins.
QA reuses runner sessions across agent calls. Reuse browsers with isolated scenario contexts; keep login within each scenario. Use selector/URL waits. Separate CLI executions start fresh sessions.
DI: Inject ports through constructors or orchestrator options; use registries and factories at composition boundaries.
REQUIRED: Propagate AbortSignal/prompt transport, resolve phase model/effort, use atomic replacement, validate DTOs, and run RTK checks.
PROHIBITED: Bind orchestration decisions to concrete runners, place HTTP transport in use cases, or bypass state adapters.
